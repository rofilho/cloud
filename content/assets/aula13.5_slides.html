Aula 13.5: Amazon S3 — Hospedagem Estática e Integração com EC2

Construa uma arquitetura desacoplada real de produção hospedando o frontend no S3 e consumindo dados privados do S3 via API REST na EC2 de forma elástica, econômica e protegida por IAM Roles.

Modalidade de Aula
🔬 Prática (Laboratório)
Tecnologias Foco
AWS S3 · EC2 · IAM · Terraform
Duração Estimada
⏳ ~85 minutos
Padrão Arquitetural
Desacoplado (Decoupled UI)
🎯 Visão Geral da Aula & Recursos

Nesta aula prática, os alunos aprenderão a hospedar arquivos de frontend (HTML/JS) com alta escalabilidade nativa no S3. O backend rodará na EC2 e fará requisições dinâmicas contra o S3 para ler dados de forma privada, utilizando um perfil de privilégio seguro via **IAM Role** (sem expor nenhuma Access Key no código do servidor).

Antes de ir para o console ou para o terminal, valide os objetivos pedagógicos da sessão com a turma:

Objetivo 2
Segurança de Identidade

Configurar uma IAM Role associada à EC2 para ler dados de forma totalmente segura no S3 sem chaves hardcoded no código.

Objetivo 3
Automação (IaC)

Escrever código Terraform completo para automatizar a criação, deploy de arquivos de dados e credenciamento de IAM.

1. Arquitetura do Lab: O Casamento de S3 e EC2 [Teoria ⏳ 10 min]

O Amazon S3 armazena objetos de forma distribuída. Por sua escalabilidade assustadora, a AWS nos permite utilizá-lo como um servidor web de alta performance para arquivos que não mudam (estáticos), tais como HTML, CSS e JavaScript. A API computacional pesada (dinâmica) fica alocada na EC2.

💼 Pergunta de Entrevista de Emprego Real

"Por que eu deveria usar o Amazon S3 para hospedar meu site institucional em vez de uma instância EC2 rodando Apache ou Nginx?"

Resposta Esperada: O S3 é totalmente serverless para hospedagem estática, eliminando o custo e o esforço de gerenciar servidores (patches, backups, logs). Ele oferece escalabilidade automática infinita e 99.999999999% (11 noves) de durabilidade nativa a um custo irrisório se comparado a manter uma máquina computacional ligada 24 horas por dia.

Siga os passos a seguir no Console AWS com a turma para criar e disponibilizar o site estático:

⚠️ Pegadinha de Escopo Global

O nome de um Bucket S3 deve ser exclusivo em toda a internet global. Se você tentar criar um bucket com o nome uniube-s3-lab, receberá um erro de conflito. Instrua os alunos a adicionarem seus nomes ou IDs no final do nome do bucket.

Roteiro da Política do Bucket (Bucket Policy)

Para tornar **apenas** a página do frontend estático pública, adicione esta política em JSON na aba Permissions do bucket:

JSON (Bucket Policy) 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::NOME-DO-SEU-BUCKET/index.html"
        }
    ]
}

3. Parte 2 — Conectando o Backend (EC2) com a API Flask — ⏱️ ~25 min

Com o frontend rodando no S3, vamos subir a API dinâmica em Flask na EC2 que consome dados no S3 de forma segura e elegante via SDK Boto3.

Roteiro de Configuração da IAM Role:

Para evitar credenciais AWS hardcoded no código, criamos um crachá de segurança para a máquina:

  • Console IAM → Roles → Create role → Serviço: EC2.
  • Anexar a política: `AmazonS3ReadOnlyAccess` (Princípio do menor privilégio).
  • Nome: EC2-S3-Read-Role.
  • Volte no painel EC2, selecione sua instância → Actions → Security → Modify IAM role → Selecione EC2-S3-Read-Role e salve.

Script de API REST Flask com Boto3

Conecte via SSH ou EC2 Instance Connect, instale dependências (sudo pip3 install flask flask-cors boto3), crie o arquivo app.py e configure o servidor REST:

Python (app.py) 
import boto3
import json
from flask import Flask, jsonify
from flask_cors import CORS
from botocore.exceptions import NoCredentialsError, ClientError

app = Flask(__name__)
# O CORS é essencial. Se não ativarmos, o navegador do usuário
# bloqueará as chamadas por virem do domínio do S3 contra o IP da EC2.
CORS(app)

# ⚠️ SUBSTITUA PELO NOME DO SEU BUCKET CRIADO NO PASSO 1!
BUCKET_NAME = "uniube-s3-lab-seu-nome"
FILE_KEY = "dados.json"

@app.route('/api/dados', methods=['GET'])
def obter_dados():
    try:
        # Inicializa o Boto3 de forma limpa. Sem senhas ou chaves!
        # Ele lê automaticamente as credenciais temporárias do perfil IAM Role da EC2
        s3 = boto3.client('s3', region_name='us-east-1')
        
        objeto = s3.get_object(Bucket=BUCKET_NAME, Key=FILE_KEY)
        conteudo = objeto['Body'].read().decode('utf-8')
        dados_s3 = json.loads(conteudo)
        
        return jsonify({
            "status": "Online",
            "servidor": "Amazon EC2 Instance",
            "data_center": "us-east-1 (N. Virginia)",
            "origem_dados": f"Lido do S3: {BUCKET_NAME}/{FILE_KEY}",
            "conteudo_s3": dados_s3
        })
    except NoCredentialsError:
        return jsonify({
            "status": "Erro de Credenciais",
            "erro": "Nao foi possivel localizar credenciais da AWS.",
            "ajuda": "Voce associou a IAM Role 'EC2-S3-Read-Role' a sua instancia EC2?"
        }), 403
    except ClientError as e:
        return jsonify({
            "status": "Erro de Acesso ao S3",
            "erro": str(e),
            "ajuda": f"Certifique-se de que o arquivo '{FILE_KEY}' existe no bucket '{BUCKET_NAME}'."
        }), 404
    except Exception as e:
        return jsonify({
            "status": "Erro Inesperado",
            "erro": str(e)
        }), 500

if __name__ == '__main__':
    # Roda na porta 80 padrão de tráfego HTTP
    app.run(host='0.0.0.0', port=80)
⚠️ Gotcha de Porta Privilegiada no Linux

No Linux, portas menores que 1024 (como a porta 80) são restritas e exigem privilégios elevados. Portanto, para rodar o app Flask diretamente na porta 80, o comando obrigatório é sudo python3 app.py. Se rodar sem sudo, ocorrerá um erro de Permission Denied.

4. Parte 3 — Automatizando o Ecossistema com Terraform — ⏱️ ~25 min

Evite cliques manuais. Vamos subir toda a mesma infraestrutura (Bucket S3 configurado, upload automático dos arquivos, IAM Role segura, Security Group com porta 80 e instância EC2 rodando a API Flask com o nome do bucket injetado) usando IaC.

Terraform (main.tf) 
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

# 1. Sufixo dinâmico para garantir exclusividade de nome no S3
resource "random_id" "sufixo" {
  byte_length = 4
}

# 2. Bucket S3 para o Frontend
resource "aws_s3_bucket" "frontend" {
  bucket        = "uniube-s3-frontend-${random_id.sufixo.hex}"
  force_destroy = true
}

# 3. Desbloqueio das configurações de acesso público ao S3
resource "aws_s3_bucket_public_access_block" "public_control" {
  bucket = aws_s3_bucket.frontend.id

  block_public_acls       = false
  block_public_policy     = false
  ignore_public_acls      = false
  restrict_public_buckets = false
}

# 4. Habilitação de Static Website Hosting no Bucket
resource "aws_s3_bucket_website_configuration" "hosting" {
  bucket = aws_s3_bucket.frontend.id

  index_document {
    suffix = "index.html"
  }
}

# 5. Política JSON de Leitura Pública (Apenas para o index.html!)
resource "aws_s3_bucket_policy" "allow_public_access" {
  depends_on = [aws_s3_bucket_public_access_block.public_control]
  bucket     = aws_s3_bucket.frontend.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid       = "PublicReadGetObject"
        Effect    = "Allow"
        Principal = "*"
        Action    = "s3:GetObject"
        Resource  = "${aws_s3_bucket.frontend.arn}/index.html"
      }
    ]
  })
}

# 6. Upload do arquivo index.html automático
resource "aws_s3_object" "index" {
  bucket       = aws_s3_bucket.frontend.id
  key          = "index.html"
  source       = "index.html"
  content_type = "text/html"
}

# 6.2 Upload do arquivo dados.json automático
resource "aws_s3_object" "dados" {
  bucket       = aws_s3_bucket.frontend.id
  key          = "dados.json"
  source       = "dados.json"
  content_type = "application/json"
}

# 7. Security Group da EC2 (Libera HTTP 80 e SSH)
resource "aws_security_group" "backend_sg" {
  name        = "backend-api-sg"
  description = "Acesso HTTP porta 80 e SSH"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# 7.5 AMI Dinâmica mais recente AL2023
data "aws_ami" "amazon_linux_2023" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# 8. IAM Role de Leitura de S3 para a EC2
resource "aws_iam_role" "ec2_s3_role" {
  name = "uniube-ec2-s3-read-role-${random_id.sufixo.hex}"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Action = "sts:AssumeRole"
        Effect = "Allow"
        Principal = {
          Service = "ec2.amazonaws.com"
        }
      }
    ]
  })
}

# 8.2 Anexar política gerenciada do S3 à Role
resource "aws_iam_role_policy_attachment" "s3_read_attach" {
  role       = aws_iam_role.ec2_s3_role.name
  policy_arn = "arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess"
}

# 8.3 Criar o Instance Profile exigido pela EC2
resource "aws_iam_instance_profile" "ec2_profile" {
  name = "uniube-ec2-s3-profile-${random_id.sufixo.hex}"
  role = aws_iam_role.ec2_s3_role.name
}

# 9. Instância EC2 configurada, automatizada e vinculada à IAM Role
resource "aws_instance" "backend" {
  ami                         = data.aws_ami.amazon_linux_2023.id
  instance_type               = "t2.micro"
  vpc_security_group_ids      = [aws_security_group.backend_sg.id]
  associate_public_ip_address = true
  iam_instance_profile        = aws_iam_instance_profile.ec2_profile.name

  # Instala dependências e inicia o app com o nome do bucket injetado pelo Terraform!
  user_data = <<-EOF
    #!/bin/bash
    dnf update -y
    dnf install python3-pip -y
    pip3 install flask flask-cors boto3
    
    # Criar o script da API Flask de forma integrada
    cat <<'INNER_EOF' > /home/ec2-user/app.py
    import boto3
    import json
    from flask import Flask, jsonify
    from flask_cors import CORS
    
    app = Flask(__name__)
    CORS(app)
    
    # Injetado automaticamente pelo Terraform!
    BUCKET_NAME = "${aws_s3_bucket.frontend.id}"
    FILE_KEY = "dados.json"
    
    @app.route('/api/dados', methods=['GET'])
    def obter_dados():
        try:
            s3 = boto3.client('s3', region_name='us-east-1')
            objeto = s3.get_object(Bucket=BUCKET_NAME, Key=FILE_KEY)
            conteudo = objeto['Body'].read().decode('utf-8')
            dados_s3 = json.loads(conteudo)
            
            return jsonify({
                "status": "Online via Terraform IaC",
                "servidor": "AWS EC2 automatizada",
                "origem_dados": f"Lido de forma segura do S3: {BUCKET_NAME}/{FILE_KEY}",
                "conteudo_s3": dados_s3
            })
        except Exception as e:
            return jsonify({
                "status": "Erro de Acesso",
                "erro": str(e)
            }), 500
            
    if __name__ == '__main__':
        app.run(host='0.0.0.0', port=80)
    INNER_EOF

    # Inicia a API REST em segundo plano sob usuário root
    python3 /home/ec2-user/app.py > /home/ec2-user/flask.log 2>&1 &
  EOF

  tags = {
    Name = "EC2-Backend-IaC"
  }
}

Resumo Estrutural

Recurso / Conceito Aplicação Prática e Definição em Uma Frase
Amazon S3 Armazenamento de objetos chave-valor elástico e sem servidor com alta durabilidade nativa.
Static Website Hosting Mecanismo que expõe arquivos HTML/JS de um bucket em um endpoint público sem gerenciar servidores.
Bucket Policy Documento declarativo JSON que impõe políticas de acesso aos recursos e objetos internos.
CORS Mecanismo de segurança do navegador que barra chamadas de domínios diferentes a menos que o backend autorize.
IAM Role Identidade e permissões temporárias atribuídas de forma lógica a um serviço da AWS para evitar credenciais estáticas no código.

🔍 Exibir Questão de Exemplo: "O gotcha do CORS no Capstone"
Enunciado: Um desenvolvedor de frontend hospedou uma interface React no S3 e tentou consultar a API Flask na EC2. A chamada travou com erro de CORS. Como o problema deve ser corrigido sem derrubar barreiras globais de segurança?

Resposta Correta: Deve-se ativar e configurar os headers de resposta CORS no código do backend da EC2 (Flask), permitindo explicitamente o domínio gerado pelo endpoint do S3 na lista de origens autorizadas (Access-Control-Allow-Origin). Alterar políticas de bucket S3 ou tornar bancos de dados públicos não afeta o comportamento de restrição de chamadas cross-origin do navegador.
